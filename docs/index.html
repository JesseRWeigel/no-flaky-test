eslint-plugin-no-flaky-test

Six rules for the mechanisms that actually make JavaScript tests flaky. Every one of them was measured against 1,912 real test files before it shipped, and every finding it produced was read by hand.

1,912test files measured
277,942lines of real test code
102findings, all hand-checked
8.8%measured false-positive rate

The corpus is 312 test files from working projects plus 1,600 shipped inside published npm packages, deduplicated by content hash. The second half matters more: it is test code written and reviewed by other people, so if a rule fires there the burden is on the rule.

Real flake is a mechanism that can fail intermittently and the author would want to know about. Deliberate means the code really is nondeterministic and the author put it there on purpose, almost always fuzz or chaos testing; the rule is right and the answer is a disable comment. False means the rule is wrong and no sequence of events can make that test fail. Only the last column counts against correctness.

Install

npm i -D eslint-plugin-no-flaky-test

// eslint.config.js
import noFlakyTest from 'eslint-plugin-no-flaky-test';

export default [
  {
    files: ['**/*.{test,spec}.{js,ts,tsx}', '**/__tests__/**'],
    ...noFlakyTest.configs.recommended,
  },
];
